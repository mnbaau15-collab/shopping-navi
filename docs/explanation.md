# 説明メモ：かんたん お買い物ナビ ＋ 課題1・課題2

> 結論から話す。聞かれたら理由、その次に具体例。分からないことは「分かりません。こう調べます」と言う。

---

## 1. 30秒で言う（アプリ全体）

庄内5市町の高齢者向けに、**近くのお店を探して、お店の公式ページと地図に案内する**Webアプリです。
HTML・CSS・素のJavaScriptだけで作り、サーバーなしで動きます。
探し方は3つ：**市町村／店名／現在地**。店舗は実在22軒を登録しています。

## 2. 技術判断（結論 → 理由）

| 判断 | 理由 |
|---|---|
| フレームワークなし | 初学者としてブラウザの基本機能から理解したかった。ビルドも不要 |
| データは `stores.js`（JSの配列） | `fetch` でJSONを読むと、`file://` で開いたときブラウザの制限で失敗するため |
| 現在地は Geolocation API ＋ハバーサイン公式 | ブラウザ標準で足りる。現在地は端末内の距離計算にだけ使い、保存・送信しない |
| 経路案内は Googleマップの URL を開く方式 | APIキーが不要。課金とキー漏洩のリスクがない |
| チラシは画像を転載せず、リンクだけ | 著作権への配慮。自動取得は規約と相手サーバーへの負担の面で避ける |
| 表示は `textContent` | 外部データをプログラムとして実行させない（XSS対策） |
| 外部リンクは `rel="noopener noreferrer"` | 開いた先のページから、元のページを操作されないようにする |
| 文字22px以上・ボタン60px以上（実際は約100px）・やさしい日本語・オレンジの暖色系デザイン | 対象が高齢者だから。コントラスト比も数値で確認した（本文15.6:1、ボタンの白文字は5.2〜7.3:1。ボタンの文字は26px超の太字で「大きな文字」にあたり、基準の4.5:1を満たす） |

## 3. ファイル構成と役割

```
index.html      画面の枠（5つの section を hidden で出し入れ）
css/style.css   見た目（色・大きさは :root の変数で一元管理）
js/app.js       画面切り替え・検索・距離計算・カード生成
data/stores.js  店舗データ（id / name / kana / city / lat / lng / officialUrl）
images/         表紙のイラスト（AIで作成した画像の一部を切り出したもの）
verify/         宿題用の検証（アプリ本体とは独立）
```

## 4. 処理の流れ（3つの探し方）

- **市町村**：`stores.filter(city === 選んだ市町)` → カードを作って並べる
- **店名**：入力を `normalizeText`（NFKC正規化 → 小文字化 → カタカナをひらがなへ → 空白と「・」を除去）で整え、店名と読みがなの**部分一致**で `filter`
- **現在地**：`navigator.geolocation.getCurrentPosition` → 各店との直線距離を計算 → 距離で `sort` → 「約 1.2 km」で表示。位置データのない店は結果に出さず、その旨を画面に出す

## 5. 工夫した点・直した不具合（具体例）

- `hidden` 属性を付けた部品が隠れなかった。原因は `display: flex` の指定が `hidden` に勝っていたこと。`[hidden] { display: none !important; }` で直した
- 距離の表示で、995m 以上が「約 1000 m」になる境目の不具合を、km 表示に切り替えて直した
- 位置データがない店は、現在地検索から外し、「行き方」ボタンも出さない。**間違った位置を入れるより、出さないほうが安全**と判断した

## 6. 課題1：トクバイからチラシのURLを取得する

**結論**：ブラウザのコンソールで `querySelectorAll("a[href]")` を使い、`/leaflets/` を含むリンクだけを `filter`、`Set` で重複を除いて、12件取得できた。

- **なぜブラウザの中でやったか**：別サイトのHTMLは、ブラウザのJavaScriptから `fetch` で読めない（CORS）。また規約に「サーバーに負荷をかける行為」「機能の解析」の禁止があり、`robots.txt` ではAnthropicのクローラーが禁止されている。**自分で開いた1ページを1回だけ**読む形にした
- **分かったこと**：URLは `/イオン/12598/leaflets/（チラシごとの番号）` の形で、番号はチラシが替わるたびに変わる。だから**アプリには個別チラシのURLを登録せず、店舗ページにリンクする**設計にした
- **もう一つの方法**：`verify/fetch-leaflets.js`（Node.jsの `fetch`）。**1回だけ実行して、同じ12件が取得できた**（2026-10-15）。`fetch` はJavaScriptを実行せずHTMLだけを受け取るので、**チラシのリンクは最初からHTMLの中に書かれている**と分かった（JavaScriptで後から作られるリンクだったら、0件になる）
- **2つの方法の違い**：コンソール＝ブラウザが組み立てたあとのページ（DOM）を読む。Node＝受け取った生のHTMLを正規表現で読む。結果が一致したことで、取り方が正しいと確かめられた

## 7. 課題2：住所2つと移動手段から経路を表示する

**結論**：Google Maps **Embed API** の directions のURLに、`key`・`origin`・`destination`・`mode` を渡して、`iframe` に表示する。

- `encodeURIComponent` で日本語の住所をURLに使える形にする
- `mode` は `driving` / `walking` / `bicycling` / `transit`
- **キーの守り方**：HTTPリファラー制限（`http://localhost:8000/*`）と、API制限（Maps Embed APIのみ）、予算アラート
- `verify/route-check.html` で動作確認済み（2026-10-15）。「酒田市東大町3-36-3 → 酒田市泉町214、車」で、地図に経路の線と、所要時間・距離（約12分・5.6km）が表示された
- **キー作成の手順**：Google Cloudの無料トライアル → 予算アラート（アラートのみ）→ Maps Embed API → APIキー作成 → 制限（HTTPリファラー `http://localhost:8000/*`、APIはMaps Embed APIのみ）。最初に自動で作られたキーは、制限が緩く、画面に写してしまったので、新しいキーを作って古いキーを削除した
- **ベストプラクティスとの関係**：「キーをクライアントコードに含めない」が推奨だが、Embed APIはURLにキーが入る。隠せない代わりに、使える場所とAPIを制限して、被害を小さくした

## 8. 想定される質問と答え

1. **なぜJSONでなくJSファイルに？** `file://` では `fetch` が制限されるので、`<script>` で読めるJSの配列にした。
2. **ハバーサイン公式とは？** 地球が丸いことを考えて、2点の緯度・経度から直線距離を求める式。道のりより短くなるので「約」と書いている。
3. **XSS対策は？** 画面に出す文字は `textContent`。URLは http/https か検査してからリンクにする。
4. **位置情報の取り扱いは？** 距離計算にだけ使い、保存も送信もしない。使う前に目的を画面で説明する。許可されなかったときは他の探し方へ案内する。
5. **APIキーの管理は？** アプリ本体はキー不要の方式。課題2では、制限をかけ、設定ファイルを分け、チャットや公開リポジトリには貼らない。
6. **なぜ個別チラシのURLを使わない？** チラシごとに番号が変わり、すぐ古くなるから。店舗ページへのリンクのほうが安定する。
7. **テストは？** 画面を模擬した環境で、検索・並べ替え・画面切り替えを自動で確認した。実際のブラウザとスマホでの確認は、これから。
8. **今後の課題は？** 位置データの残り（確認待ち）、スマホ実機（HTTPSで公開が必要）、鶴岡市の追加、自動テストの整備。
9. **AIをどう使った？** コードの作成・調査はClaudeに手伝ってもらった。**何を作るか、案の選択、データ（URL・位置）の確認、動作の確認は自分で行った。** 説明できる範囲を正直に話す。

## 9. 用語メモ

| 言葉 | 一言 |
|---|---|
| DOM | ブラウザがページの中身を、プログラムで扱える木の形にしたもの |
| `querySelectorAll` | 条件に合う部品を全部探す |
| `map` / `filter` | 全部に同じ処理 / 条件に合うものだけ残す |
| `Set` | 重複をなくす入れ物 |
| CORS | 別サイトの中身を、ブラウザのJSが勝手に読めないようにする仕組み |
| `robots.txt` | サイトが、機械的なアクセスについて出している決まり |
| URLエンコード | 日本語などを `%E3...` に変えること |
| APIキー | 誰が使っているかを伝える合言葉。漏れると他人に使われる |
| HTTPS / localhost | 位置情報が使える条件（安全な通信、または自分のパソコン内） |
| XSS | 悪意のあるプログラムを、画面に紛れ込ませる攻撃 |
